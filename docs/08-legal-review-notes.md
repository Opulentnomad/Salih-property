# ملاحظات للمستشار القانوني (قبل نشر سياسة الخصوصية والشروط)

> هذا ملخص تقني بما يفعله التطبيق فعليًا، لتبني عليه المراجعة القانونية. **لستُ مستشارًا قانونيًا، والمسودتان (`docs/legal/`) نقطة بداية لا رأي نظامي.** الأقواس `[ ]` في المسودتين أماكن تحتاج تعبئة أو تحققًا. تعديل النص: عدّل ملفات `md` ثم `cd backend && npm run legal` لتحديث صفحات التطبيق.

## ١) خريطة البيانات (كما في الشيفرة الحالية)
| البيانات | أين تُحفظ | متى | الاحتفاظ/الحذف |
|---|---|---|---|
| مفضلة، رحلات، لغة/وضع داكن، آخر وجهات شوهدت، علامات المستندات | متصفح المستخدم (`localStorage`) فقط | دائمًا | بيد المستخدم (مسح بيانات الموقع) |
| بريد إلكتروني، بصمة كلمة المرور (scrypt)، تاريخ الموافقة ونسختها | قاعدة الخادم | عند إنشاء الحساب | حتى حذف الحساب (`DELETE /api/me`) |
| مفضلة المسجّل | قاعدة الخادم | عند الدخول والتبديل | تُحذف مع الحساب |
| مراجعة (نص، تقييم) | قاعدة الخادم | عند الكتابة | تُنشر بعد إشراف باسم «مسافر» دون البريد؛ **تُحذف** مع الحساب |
| عنوان IP ووقت ومسار الطلب | سجلات الخادم + عدّاد تحديد المعدّل (ذاكرة) | كل طلب | [مدة سجلات المنصة؛ تُضبط عند النشر] |
| سجل التدقيق (إجراءات المحررين) | قاعدة الخادم | إجراءات الإدارة | معرّف المحرر يُمحى عند حذف حسابه |
| اشتراكات التنبيهات | **محلية فقط حاليًا** (جدول الخادم موجود ولا تستخدمه الواجهة) | — | تنبيه: عند تفعيل الإرسال مستقبلًا تتغير السياسة |

**لا يجمع التطبيق:** أرقام جوازات/هويات، موقعًا جغرافيًا، صورًا، بيانات دفع. لا ملفات تعريف ارتباط ولا تحليلات.
**أطراف ثالثة:** لا اتصال من متصفح الزائر بأي خادم خارجي (فحصتُ ذلك آليًا على الصفحات الرئيسية): الخطوط مستضافة محليًا، وأسعار الصرف يجلبها الخادم نفسه من `open.er-api.com` يوميًا دون بيانات مستخدم. روابط الحجز الحالية وهمية (`example.com`).

## ٢) ما نُفِّذ تقنيًا ليتوافق مع ما تعد به السياسة
- موافقة صريحة (مربع اختيار) عند التسجيل، تُسجَّل بوقتها ونسخة السياسة، ويرفض الخادم التسجيل بدونها.
- حق الاطلاع/النسخة: `GET /api/me/export` (JSON، بلا بصمة كلمة المرور).
- حق الإتلاف: `DELETE /api/me` بكلمة المرور؛ يحذف الحساب والمفضلة والمراجعات والتنبيهات، ويمحو معرّفه من سجل التدقيق. لا يُسمح بحذف آخر مدير.
- إصلاح تسريب: كان اسم كاتب المراجعة العلني يُؤخذ من بريده؛ صار «مسافر».
- إزالة اتصال Google Fonts (كان يرسل IP كل زائر إلى Google).
- **لم يُنفَّذ بعد:** تصحيح البريد من داخل التطبيق، وسحب الموافقة بصيغة مستقلة (الحذف هو البديل)، وحذف النسخ الاحتياطية آليًا عند الحذف (يدوي أو بانتهاء مدة الاحتفاظ).

## ٣) أسئلة للمستشار
1. **الصفة النظامية:** هل نحن «جهة تحكم»؟ هل يلزم تسجيل لدى الجهة المختصة أو تعيين مسؤول حماية بيانات؟ (حسب حجم المعالجة وطبيعتها).
2. **الأساس النظامي** لكل غرض: موافقة أم تنفيذ خدمة أم مصلحة مشروعة (سجلات الأمان وIP)؟
3. **نقل البيانات خارج المملكة:** المنصات المقترحة (Render وFly.io) خوادمها خارج المملكة. ما الضوابط والشروط المطلوبة؟ هل يلزم موقع استضافة داخل المملكة؟
4. **الإبلاغ عن الحوادث:** المدة والجهة والمحتوى المطلوب.
5. **مدد الاحتفاظ** المقبولة (السجلات، النسخ الاحتياطية).
6. **الأطفال:** السن الأدنى المناسب (المسودة تقول 18) وهل يلزم إذن ولي الأمر.
7. **الإعلانات والعمولات:** متطلبات الإفصاح عن روابط الشركاء (نظام التجارة الإلكترونية/الإعلان) وصياغة بند الشركاء.
8. **إخلاء المسؤولية:** مدى صحة حدود المسؤولية ونفي الضمان للمعلومات الاسترشادية (خصوصًا بيانات التأشيرات) وفق الأنظمة السعودية وحماية المستهلك.
9. **النظام الواجب التطبيق والاختصاص القضائي** وصياغة بند الشكاوى.
10. **تراخيص البيانات المفتوحة:** صياغة الإسناد لـ Passport Index (MIT) وmledoze/countries (ODbL يشترط الإسناد والمشاركة بالمثل لقاعدة البيانات المشتقة).
11. **هل نحتاج إشعار ملف تعريف الارتباط/التخزين المحلي** رغم عدم استخدام ملفات تعريف تتبع؟
12. **اللغة:** هل يلزم نص إنجليزي موازٍ؟ (الواجهة عربية حاليًا.)

## ٤) قبل النشر
- [ ] عبّأ جميع الأقواس `[ ]` (اسم الجهة، البريد، المدد، موقع الخوادم، الجهة المختصة).
- [ ] أعد توليد الصفحات: `cd backend && npm run legal` ثم `npm run preview`.
- [ ] اضبط مدة سجلات المنصة بما يطابق السياسة، وتحقق أنها لا تحتفظ بـ IP أطول.
- [ ] غيّر نسخة السياسة `POLICY_VERSION` في `backend/src/routes/account.js` عند كل تعديل جوهري، وقرّر هل يُطلب من المسجّلين موافقة جديدة.
- [ ] إن أضفت بريدًا إلكترونيًا للتنبيهات أو تحليلات أو إعلانات: حدّث السياسة والموافقات **قبل** تفعيلها.
