# نشر سفرنا على الإنترنت

خادم واحد (Node) يقدّم الواجهة والـ API معًا، وقاعدة بيانات SQLite في قرص دائم. هذا يكفي للإطلاق الأول (آلاف الزوار). الأسعار والمناطق وصيغ ملفات المنصات تتغير، فراجع توثيق المنصة وقت التنفيذ.

> **ما تحققتُ منه:** شغّلتُ الخادم بوضع الإنتاج من نسخة نظيفة (تثبيت `npm ci --omit=dev`): يرفض الإقلاع بلا `JWT_SECRET`، ويعمل بعده، ويقدّم الواجهة، ويرفض الوصول لملفات القاعدة، وتُضاف رؤوس HSTS وCSP. **لم أستطع بناء صورة Docker** (لا يوجد Docker daemon في بيئتي)، ولا نشرتُ على أي منصة. جرّب البناء محليًا أولًا: `docker build -f backend/Dockerfile -t safarna .`

## أسرع طريقة لعرض الموقع فقط (بدون حسابات)
ارفع الملف المستقل `preview.html` على أي استضافة ثابتة (GitHub Pages أو Netlify Drop أو Cloudflare Pages) وأعد تسميته `index.html`. يعمل بكل الوجهات والتقويم والمقارنة، لكن **بلا حسابات ولا مراجعات ولا لوحة إدارة**. مناسب لعرضه على أصدقاء أو مراجعين. لإعادة بنائه: `cd backend && npm run preview`.

## النشر الكامل

### قبل أي منصة
1. ارفع المشروع إلى مستودع GitHub (هو موجود في الفرع الحالي؛ ادمجه في `main` عبر Pull Request).
2. جهّز قيمًا سرية: `JWT_SECRET` (`openssl rand -hex 32`)، وبريد وكلمة مرور قوية للمدير (`ADMIN_EMAIL` و`ADMIN_PASSWORD`، ١٢ حرفًا فأكثر).

### الخيار أ: Render (الأسهل بالواجهة)
1. أنشئ حسابًا ثم **New ← Blueprint** واختر المستودع. سيقرأ `render.yaml` ويجهّز الخدمة والقرص (١ جيجابايت).
2. أدخل `ADMIN_EMAIL` و`ADMIN_PASSWORD` حين يطلبها. `JWT_SECRET` يُولَّد تلقائيًا.
3. انتظر البناء، ثم افتح رابط الخدمة `https://<الاسم>.onrender.com` وتحقق من `/api/health`.
4. **القرص الدائم يحتاج خطة مدفوعة.** على الخطة المجانية تُمسح القاعدة عند كل إعادة نشر، فلا تستخدمها للإطلاق.

### الخيار ب: Fly.io (بالطرفية)
```bash
fly launch --no-deploy --copy-config          # يستخدم fly.toml (غيّر اسم التطبيق إن لزم)
fly volumes create safarna_data --size 1 --region fra
fly secrets set JWT_SECRET=$(openssl rand -hex 32) ADMIN_EMAIL=you@example.com ADMIN_PASSWORD='كلمة-مرور-طويلة-وقوية'
fly deploy
fly status && curl https://<التطبيق>.fly.dev/api/health
```
جهاز واحد فقط (`min_machines_running = 1`)؛ لا تزد عدد الأجهزة لأن SQLite لا تتشارك بين أجهزة.

### النطاق وHTTPS
اربط نطاقك من لوحة المنصة (Custom Domain) وأنشئ سجل DNS الذي تطلبه. الشهادة تصدر تلقائيًا. بعدها اضبط `CORS_ORIGIN` فقط إن كانت الواجهة ستُخدم من نطاق مختلف عن الـ API (الإعداد الحالي: نفس النطاق، فلا حاجة).

## بعد أول تشغيل
- افتح `/admin.html` وسجّل بحساب المدير، وغيّر كلمة المرور إن كانت مؤقتة. **حساب المدير يُنشأ عند أول تشغيل فقط** (والمتغيران يُهملان بعدها).
- لترقية مستخدم آخر (مراجع أو محرر) بعد أن يسجّل بنفسه، من طرفية الخدمة (`fly ssh console` أو Shell في Render):
  `cd /srv/backend && npm run set-role -- reviewer@example.com reviewer`
- راجع الوجهات الأولى من `docs/06-review-list.md`، وأكّد أو عدّل أحداث التقويم من تبويب «التقويم».

## النسخ الاحتياطي (مهم: القاعدة ملف واحد)
- `cd /srv/backend && npm run backup` ينسخ القاعدة بأمان أثناء العمل إلى `/data/backups` ويحتفظ بآخر ١٤ نسخة.
- النسخ على نفس القرص لا تحمي من فقدانه. انسخها خارج المنصة بانتظام (تخزين سحابي أو جهازك)، وفعّل لقطات القرص إن وفّرتها المنصة.
- الاستعادة: أوقف الخدمة، استبدل `/data/safarna.db` بالنسخة، وأعد التشغيل.
- لخطة أقوى لاحقًا: Litestream لنسخ مستمر، أو الانتقال إلى PostgreSQL.

## مراقبة وتراجع
- فحص الصحة `GET /api/health` (تستخدمه المنصة تلقائيًا). أضف مراقبًا خارجيًا (UptimeRobot أو Better Stack) ينبّهك عند التوقف.
- كل دفع إلى المستودع يشغّل `CI` (الاختبارات و`npm audit`). لا تنشر إن فشل.
- للتراجع: أعد نشر الإصدار السابق من لوحة المنصة (Render: Rollback، Fly: `fly releases` ثم `fly deploy --image`). القاعدة لا تتأثر.

## قائمة ما قبل الإطلاق العام
- [ ] راجعت وجهات الدفعة الأولى (٢١) من مصادر رسمية ونشرتها من لوحة الإدارة، وفحصت تحذيرات السفر السعودية لكل واحدة.
- [ ] كل ما لم يُراجع يظهر «غير موثّقة رسميًا» (هذا يحدث تلقائيًا) وراجعت صياغة التنبيه مع مستشار قانوني.
- [ ] صفحة **سياسة الخصوصية** وشروط الاستخدام (نظام حماية البيانات الشخصية PDPL): ما نجمعه (بريد، مفضلة، رحلات) وكيف يُحذف الحساب.
- [ ] روابط الحجز الوهمية (`example.com`) استُبدلت بروابط شركاء حقيقية مع إفصاح عن العمولة.
- [ ] `ADMIN_PASSWORD` قوية، ولا كلمات مرور افتراضية في أي بيئة.
- [ ] جرّبت التسجيل والمفضلة والمراجعة والنشر من لوحة الإدارة على الجوال بعد النشر.
- [ ] قرار إقامة البيانات: المنصتان أعلاه لا تقدمان منطقة داخل السعودية. إن كانت متطلباتك تفرض استضافة داخلها أو إقليميًا (مثل مزودين سحابيين لديهم مناطق في الخليج) فخطط لنقل النشر.

## حدود هذا الإعداد
- **جهاز واحد:** SQLite لا تتوسع أفقيًا. عند نمو الاستخدام انقل المخطط (`docs/03-database-schema.sql`) إلى PostgreSQL.
- **لا بريد إلكتروني ولا رمز تحقق للجوال ولا استعادة كلمة المرور** بعد. من ينسى كلمة مروره لا طريقة آلية لاستعادة حسابه.
- **صفحة `/admin.html` مفتوحة للوصول** وتحميها كلمة المرور والصلاحيات فقط. فكّر بتقييدها بعنوان IP أو بطبقة Cloudflare Access.
- **التنبيهات (Push/بريد)** تُخزَّن اشتراكاتها فقط ولا يُرسل منها شيء.
